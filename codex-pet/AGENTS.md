# Codex Pet 开发规则

本文件适用于 `codex-pet/`。继承根目录的沟通、uv 使用、代码风格和提交约定；此目录维护 Codex 角色素材，Windows 桌宠的 `vn_pet/`、前端及启动目录保持原结构。

## 工作入口

- 调整角色范围、形象或动作前，阅读[重要决策](docs/decisions.md)及对应 `design/<版本>/` 的主形象与规格。
- 调整目录、推进制作或准备交付时，阅读[制作流程](docs/production.md)；术语有歧义时查 [CONTEXT.md](CONTEXT.md)。
- 修改已有成品前，核对 `packages/<包 ID>/` 与 `releases/<包 ID>.json`，区分设计修订和图集契约版本。

## 文件与记录

成品在 `packages/`，已确认设计在 `design/`，重要决策在 `docs/decisions.md`，验收摘要与批准哈希在 `releases/`；这些是纳入 Git 的持续开发依据。

参考照片、原型、生成过程、逐轮 QA、旧包和提交草稿按制作流程放入 `.work/`。已形成的稳定结论应更新正式文档，不能只留在 `.work/`。历史记录中的旧状态和路径用于追溯，不作为当前授权或设计基准。

成品应可独立复制使用，预览资源限于包内。保留旧版的要求落实为不同包 ID；批准图集和主形象的变更须有对应的新制作、验收记录，不能只改哈希让检查通过。

## 素材检查与交付

修改成品、设计主形象或发布记录后，从仓库根目录执行：

```powershell
.\.venv\Scripts\python.exe codex-pet/tools/verify_package.py
```

修改预览后直接打开包内 `preview.html`，查看资源加载及受影响的动作或注视表现。仅改文档时核对引用与状态即可；素材和文档整理不要求建立测试套件，Windows 应用测试只在其代码或行为受影响时运行。

交付前同步成品说明、有效决策和发布记录，并检查 Git 范围，确保 `.work/` 仍由本目录 `.gitignore` 排除。不要将完整制作流水账复制到本文件。
